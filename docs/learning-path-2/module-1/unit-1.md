# Learning Path 2 — Module 1, Unit 1: Introduction

## Welcome

In this unit, we begin exploring the core architectural components of Microsoft Azure. These components explain how Azure is organized, where its services run, and how you organize and manage the resources you create.

We'll learn step by step, using practical examples such as a school in Saboti that wants to host a website, store student resources, and manage staff access.

## What you'll learn in this module

By the end of this module, you should be able to describe:

- **Azure physical infrastructure:** datacenters, regions, region pairs, sovereign regions, and availability zones.
- **Azure management infrastructure:** resources, resource groups, subscriptions, and management groups.
- **How these pieces fit together:** how Azure provides physical infrastructure and how customers organize the services they use.

## A simple picture

Imagine a school wants to put its website online.

- Microsoft operates the physical datacenters that host cloud infrastructure.
- Azure groups datacenters into geographic **regions**.
- The school creates Azure **resources**, such as a web app or storage account.
- The school organizes related resources into a **resource group**.
- An Azure **subscription** provides a scope for access and billing.
- A **management group** can help organize multiple subscriptions.

We'll unpack each term carefully in the following units. You do not need to memorize all the terms at once; focus first on understanding what each one is for.

## Quick knowledge check

**Question:** Which statement best describes the purpose of this module?

A. To learn how to write a mobile app in a particular programming language.  
B. To understand how Azure's physical locations and management structure support cloud services.

**Answer: B.** This module introduces Azure's physical infrastructure and the organizational structure used to manage Azure resources.

## Key takeaway

Azure architecture has two useful perspectives: **where the infrastructure runs** and **how cloud resources are organized and managed**. This module introduces both.
